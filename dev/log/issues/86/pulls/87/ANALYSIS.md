## Root causes and reproduction

1. **JavaScript release on main:** `git show origin/main:package.json` resolves from the repository root even when executed in `js/`. Before this work the root manifest was absent; after adding a release-tool manifest it would silently select the wrong version. Main run 43602368001 records the fatal lookup at lines 13123–13131 in `ci-logs/main-js-43602368001.log`. The new test creates a root manifest with version 99.0.0 and a JS manifest with 1.2.3; the old lookup fails the assertion (saved `verification/remote-version-before.log`). `package-version.mjs` now uses the explicitly package-relative Git path `ref:./package.json`; the same test passes (`remote-version-after.log`). Ordinary local reads remain package relative. The shared helper is used by the actual release script.
2. **Python publish on main:** run 43602367955 was rejected by PyPI with `invalid-publisher` and “valid token, but no corresponding publisher” (`ci-logs/main-python-43602367955.log`, search `invalid-publisher`, around line 5040). This is an external PyPI account configuration, independent of the merged package updates. Existing repository preflight code already distinguishes missing publisher/package, gives the exact repository/workflow/owner runbook, and tests those paths. PR tests/builds run without a publishing identity; main publishing continues to fail with explicit instructions until configured. No fake successful release or weakened publish check is introduced.
3. **New-tool diagnostics:** current Ruff reformats old import/wrapping syntax and Python 3.15 exception clauses; mypy 2.4.1 exposes previously unannotated test functions under the existing `--strict` pre-commit policy; Rust 1.100 Clippy recommends let chains. Fix the annotations/control flow instead of suppressing warnings, excluding test files or relaxing strictness. New ESLint flags an obsolete `no-loss-of-precision` suppression; remove the unused directive.
4. **First pushed CI correction:** parity run 43607090521 detected updated Python/Rust/C# library paths without JavaScript source (lines 538–545 in `ci-logs/parity-43607090521.log`). Complete the native string API cleanup in JS quoting/unquoting (`replaceAll` for literal substitutions); all 596 existing codec tests verify the exact format. The parity gate is retained unchanged and no opt-out marker is used.
5. **Windows hash-locked Python install:** the first lock was resolved on Linux and omitted Windows-only colorama/pywin32-ctypes. Job 132484609687 rejected the missing colorama hash before tests (around line 420 of `ci-logs/python-windows-job-132484609687.log`). Regenerate with `uv pip compile --universal --generate-hashes` so platform markers and all platform hashes are included. Linux still passes 536 tests; the Windows matrix verifies the corresponding installation.
6. **npm CLI's bundled security dependencies:** the official latest npm 12.2.2 tarball includes glob 13.0.6 and minimatch 10.2.5. Both match reviewed advisories; audit reports 21 propagated moderate package findings from two advisories. Consumer overrides do not replace bundled copies. Keep the strict nonzero audit, run both lockfile audits even when one fails, and update the existing upstream report with the exact released versions and reproduction. A clean JavaScript application audit does not establish a clean package-manager tool. The zero-advisories criterion remains unfinished pending a fixed official npm release.
7. **C# CodeQL buildless restore:** the successful scan in run 43607982453 concealed failed restores: the extractor substitutes empty targeting-pack paths, cannot resolve .NET 11 references, and guesses package names from XML test strings. Reproduce the targeting-pack failure and successful real restore/build with `experiments/issue-86/codeql-restore.sh`. Switch C# alone to CodeQL's documented manual mode and trace locked solution/example/interop builds. Run 43608925924 verifies all three builds succeed and analysis completes; report the extractor defect upstream in github/codeql#23133. The current CodeQL CLI remains 2.27.4; no older scanner is pinned as a workaround.

## Existing libraries/components considered

- **npm-check-updates** crosses major manifest ranges; npm update alone does not. Used the current registry dist-tags and ncu discovery rather than treating a successful compatible update as latest. Preserve parent API contracts for indirect majors; each exception has concrete ancestry.
- **uv pip compile** supplies a small, hashed, pip-compatible lock from the existing pyproject optional development extra. Introducing Poetry would duplicate project metadata; a full new workspace format is unnecessary. CI installs the same hashes and builds without isolation from the explicitly locked build dependencies.
- **cargo-edit / cargo upgrade** can rewrite incompatible requirements; latest crates.io requirements were applied consistently to all six manifests, then Cargo regenerated each lock. A plain cargo update would not have raised parser requirements or editions. One shared rust-toolchain.toml keeps experiments aligned.
- **dotnet native package list** provides current/outdated/vulnerability JSON without adding another project tool. NuGet's minimum-version selection otherwise leaves old transitives; explicit test-only PrivateAssets references raise them and four lockfiles preserve the exact graph. No extra telemetry code is introduced into the codec library.
- **Dependabot versus Renovate:** the existing bot already supports grouped cross-ecosystem updates. Extend it instead of adding a second competing bot. [GitHub supported ecosystems](https://docs.github.com/en/code-security/dependabot/ecosystems-supported-by-dependabot/supported-ecosystems-and-repositories) and [Dependabot core](https://github.com/dependabot/dependabot-core) document the relevant SDK/toolchain/hook support.
- **Node native APIs:** RegExp.escape replaces the changeset name's handwritten regex escaping; replaceAll handles literal quote substitutions without regex patterns. Current runtimes remove the npm-11-specific installer selection logic. Keep codec browser fallbacks: a server runtime upgrade does not authorize dropping browser support.
- **links-notation 0.31.5 native helpers:** compared current parseIndentedDocument and escaping APIs with this repository's legacy reference semantics. Immediate-child conversion and new quote rules are not equivalent to the codec's nested graph/legacy formatting contract; substituting them would remove supported behavior. Retain compatibility handling and existing parser APIs. The actual missing Python typing marker is reported, rather than pretending `ignore_missing_imports` is an upstream fix.
- **command-stream and lino-arguments:** current released packages replace remote source evaluation. A single package lock and narrow parser overrides avoid four implicitly different release graphs. Their published meta-language/lino-env dependency metadata still lags source and was reported upstream; an actual command execution plus lenv/CLI precedence test exercises this graph.

## External blockers and limits

The zero-unresolved-advisories criterion and green PR Security check are blocked on npm's released bundle. [GHSA-3g3m-2fjr-6pw4](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4) is fixed in glob 14.0.2 and [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249) in minimatch 11.0.1, but npm 12.2.2 still ships older internal versions. The registry's latest CLI has no supported fixed bundle. Updating those bundled major APIs locally would create a separate unvalidated npm distribution; consumer overrides demonstrably do not do it. Exact audit JSON, registry receipts and upstream report are preserved. Keep both audits enabled and their failure visible until a fixed official CLI can be installed and verified.

The fully green default-branch release criterion is also unfinished. Evidence is the PyPI `invalid-publisher` response for main and the package/preflight lookup. An owner must configure the PyPI project/pending Trusted Publisher with owner `link-foundation`, repository `lino-objects-codec`, workflow `python.yml` and the environment claimed by the workflow (currently empty), following the existing runbook. This requires PyPI account authority unavailable in this workspace. The PR cannot configure a foreign service account merely by editing YAML. It also cannot change default-branch code without an owner merging the PR; no direct merge is authorized. Keep these criteria unfinished and the PR unmerged. No claim of goal completion is made on the basis of local tests or partial CI success.
